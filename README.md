# APNG Studio 使用說明

APNG Studio 是給動態貼圖使用的排幀與匯出工具。它會在匯出前依照 APNG 與 LINE 驗證器的實際算法檢查影格，避免 apngasm 顯示的張數和 LINE 收到的張數對不上。

支援的來源檔：`.clip`（Clip Studio Paint）、`.procreate`（Procreate）、`.psd` / `.psb`（Photoshop 及其他能匯出 PSD 的軟體）。

## 怎麼開啟

下載 `APNG-Studio-x.y.z-portable.exe`，點兩下即可使用，不需要安裝。

## 專案

打開程式先看到**專案列表**，選一個進去或按「＋ 新專案」挑一個來源檔（`.clip` / `.procreate` / `.psd`）。
編輯畫面永遠綁在某一個專案上，左上角看得到專案名稱與「已儲存 / 有未儲存的變更」。

- `Ctrl+S` 存回目前這個專案，不會再問你要存去哪
- `Ctrl+Shift+S` 另存成新專案並切過去
- 有未存檔的變更時，回專案列表、開新專案、換來源檔、關視窗都會先問
- 每 30 秒會寫一份**自動存檔**（不會蓋掉你手動存的那份）。下次打開這個專案時，
  如果自動存檔比手動存檔新，會問你要不要復原
- 專案卡片可以改名、複製、刪除。來源檔被搬走時，開啟時會讓你重新指定

存檔放在 `%APPDATA%\APNG Studio\projects\<專案 id>\`，一個專案一個資料夾，
所有寫入都是先寫暫存檔再換檔，寫到一半斷電也不會弄壞既有的存檔。
舊版的 `projects.json` 會在第一次啟動時自動匯入（原檔會留成 `projects.legacy.json`）。

## 素材（一個專案可以放很多個檔案）

一組 LINE 貼圖有 8–40 張，每張通常是一個獨立的 `.clip`，所以一個專案可以掛很多個來源檔。

左側「素材」面板列出這個專案用到的所有檔案：

- 點一列就切過去編輯那個檔案的圖層
- `＋ 加入素材` 或直接把檔案拖進編輯器，就會加進素材庫（不會再叫你開新專案）
- `連結`：檔案被搬走或改名時重新指向新位置，影格的對應完全不會跑掉
- `移除`：**只從專案移除，不會刪掉磁碟上的原始檔**。移除前會先告訴你它被幾個影格、
  哪幾格貼圖用到，確認後那些影格才會變空白

每一格影格都記得自己是從哪個檔案來的，所以切換素材不會弄亂已經排好的東西；
影格上會顯示來源檔名（當它不是目前正在編輯的那個檔案時）。

打開專案時如果有素材找不到檔案，只有那一筆會標成紅色「找不到檔案」，
其他素材照常可用，用「連結」修好即可。

## 基本流程

1. 建立或開啟專案。常用的草稿資料夾可以在設定裡指定，之後用「從草稿資料夾」（`Ctrl+D`）直接列出來點開。
2. 按影格軌上的「帶入 CSP 時間軸」，或從左側把圖層拖到下方影格軌。
3. 影格中間可以留空，空格會自動延續前一格的圖片。
4. 按播放，直接確認速度與動畫效果。
5. 在右側設定輸出尺寸、FPS 與播放次數。
6. 選擇 APNG 或 GIF，按匯出。

## 圖層軌道

影格軌可以疊很多層，就是一般認知的圖層：`＋ 圖層` 新增一條軌道，最上面那條畫在最前面。
每條軌道有自己的影格內容與畫面調整（縮放、位移 X／Y、不透明度都有拉條），右側「畫面調整」
永遠是在調目前選中的那條軌道。用 ▲▼ 調整前後順序，✕ 刪除。

影格可以批次操作：`Ctrl+點` 加選、`Shift+點` 選一段、在影格條空白處拖曳可以框選，
`Ctrl+A` 全選、`Esc` 取消。選好之後拖到任一格就整批搬過去（按住 `Alt` 是覆蓋而非搬移）。
插入／刪除影格會同時作用在所有軌道上，時間軸才不會對不齊。

## 不會弄丟進度

- 調低格數時，被切掉的影格會先收在暫存裡，格數加回來就原封不動回來。
- `Ctrl+Z` 復原、`Ctrl+Shift+Z`（或 `Ctrl+Y`）重做，涵蓋排幀、補幀、圖層增減。
- 「清空畫布」會清掉所有影格與多餘圖層但保留開啟的檔案，按之前會先確認，也可以 `Ctrl+Z` 復原。
- 「＋ 插入一格」會插在目前選取影格的**右邊**（所有圖層一起），游標會跟著移到新格子。

## 為什麼兩種幀數不一樣？

「時間軸格數」是你排了幾格；「實際 APNG 幀數」是檔案真正包含幾幀。連續一樣的圖片會被合併成一幀，並把停留時間加長。這是 APNG 規格與 LINE 驗證器的行為，不是工具算錯；以前 apngasm 張數對不上，原因就是這個。

## LINE 規格速查

| 項目     | 動態貼圖                             | 動態表情貼            | 主要圖片              |
| -------- | ------------------------------------ | --------------------- | --------------------- |
| 尺寸     | 最大 320 × 270，寬或高至少一邊為 270 | 固定 180 × 180        | 固定 240 × 240        |
| 幀數     | 5–20 幀                              | 5–20 幀               | 5–20 幀               |
| 單次播放 | 1、2、3 或 4 秒                      | 最多 4 秒             | 1、2、3 或 4 秒       |
| 播放次數 | 1–4 次，總計最多 4 秒                | 1–4 次，總計最多 4 秒 | 1–4 次，總計最多 4 秒 |
| 檔案大小 | 1 MB 以內                            | 300 KB 以內           | 1 MB 以內             |
| 每組張數 | 8、16 或 24 張                       | 8–40 張               | —                     |

三種用途都要匯出成透明背景的 APNG（`.png`）。聊天縮圖尺寸是 96 × 74。

## 畫面調整

原稿比例和輸出尺寸不同時，畫面可能留白或被裁切。「符合」會保留完整畫面，邊緣可能留白；「填滿」會放大到鋪滿輸出範圍，超出的部分會裁掉。還可以調整縮放比例與 X／Y 位移，把主體移到最合適的位置；預覽顯示的外框就是實際輸出邊界。

## 一鍵符合規範（補幀）

影格不到 LINE 要求的 5 幀時，會用「來回播放」把不同的畫面補到 5 幀以上（A B C → A B C B），
並自動挑一組讓單次播放剛好是 1／2／3／4 秒的 FPS 與播放次數。

每一幀的延遲一律對齊到 10 毫秒的整數倍，寫檔時用 `delay_den=100`。這是因為 LINE 的驗證器
會把 fcTL 的延遲換算成 1/100 秒再加總，只要有一幀不是整數的百分之一秒，尾數就會被截掉，
總長度變成 0.96 秒之類的值，上傳時就會看到「播放時間請設定為 1 秒、2 秒、3 秒或 4 秒」。

## GIPHY 上傳

在設定裡填好 API Key 後，「上傳到 GIPHY」會先開確認視窗。

> **上傳失敗回「Unauthorized」時，先看「使用者名稱」欄位。**
> 那一欄必須是這把金鑰擁有的 GIPHY 頻道，填了別人的或不存在的名稱就會被回 401，
> 跟金鑰本身沒有關係 —— **沒有頻道就讓它空著**。
> developers.giphy.com 一般的 API key 就可以上傳，不需要另外申請 production key。
>
> 想單獨測金鑰，可以跑
> `GIPHY_API_KEY=你的金鑰 npm run try:giphy -- 某個.clip`，
> 它會用真的檔案產一支 GIF 打真的 API，並分辨是金鑰問題還是程式問題。
> 另外開發版與打包版的設定是分開存的（`%APPDATA%\Electron` 與 `%APPDATA%\APNG Studio`），
> 金鑰不會互通。
> 標籤用 chip 編輯器輸入：
> 打字後按 Enter 或逗號新增、✕ 移除、可貼上「a, b, c」自動拆開；
> 用過的標籤會記住，下次顯示在「最近用過」直接點選。上傳成功會給 GIPHY 頁面與直連網址。

## 貼圖組

編號格本身就是一份動畫文件，點任一格就會直接進去編輯；點空格時會自動建立一份新文件。
改完回到貼圖組，該格的縮圖會自動更新，不需要另外按「存入貼圖組」。格子之間可以直接拖曳換順序。
`main` 與 `tab` 兩張商品圖片可以直接從檔案總管把 PNG 拖進去（編號格也吃拖放）。
打包出來的檔名是 `01.png`…`NN.png` 加上 `main.png`、`tab.png`，就是 LINE 要的結構。

「帶入 CSP 時間軸」會讀取目前 `.clip` 自己的動畫資料夾與關鍵影格；有多條動畫軌時，
可以從選單挑一條帶入目前軌道。不同 `.clip`、不同文件 FPS 與經過修剪的動畫片段都會各自正確換算。
工具只在關鍵影格填入對應的同名 cel 資料夾；中間空格會自動延續前一格，因此排幀畫面簡潔，
播放結果仍與 CSP 時間軸一致。

### 批次匯入資料夾

在貼圖組按「批次匯入資料夾」，可以一次帶入整個資料夾裡的 `.clip`、`.procreate`、`.psd` / `.psb`。
檔名**開頭的數字**就是格號：`01.clip`、`001_揮手.clip`、`2開心.psd` 會分別放進第 1、1、2 格；
前導零和數字後面的文字都不影響判讀。沒有以數字開頭、格號為 0，或超出目前貼圖張數的檔案會跳過。

如果目標格已有內容，可以選「覆蓋並匯入」、「保留衝突格並匯入其餘」，或直接取消整次匯入。
同一個格號若對到兩個以上的檔案，為了避免猜錯，該格的檔案會全部跳過，不會任選一個覆蓋。

每個 `.clip` 會建立綁定來源的可編輯文件，並自動帶入**第一個 CSP TimeLine 的全部動畫軌**；
`.procreate`、`.psd` / `.psb` 也會建立綁定來源的空文件，方便進去自行排幀。完成後會顯示成功匯入格數、
覆蓋的格號、跳過的檔案與原因、無法解析的壞檔，以及未帶入動畫、額外 TimeLine 和 CSP 時間軸警告。

## 匯出檔名

存檔對話框的預設檔名是**月日_時分**，例如 8 月 23 日 03:19 匯出就是 `0823_0319.png`，
並且預設存在原本 `.clip` 檔的同一個資料夾。連續匯出多版不會互相覆蓋。

## 給開發者

本專案為了不散布委託人的原稿，`assets/samples/`（測試用 `.clip`）與
`assets/golden/`（由它產生的比對基準圖）**未包含在 repo 內**。
因此 clone 之後 `npm run verify` 與 `npm run smoke` 需要自備 `.clip` 檔並自行建立基準。
另外，`npm run verify:timeline` 需要 `assets/samples/09.clip`（同樣不在 repo 內）；
`npm run verify:migration` 與 `npm run verify:pack` 是純資料測試，不需要樣本檔。

```bash
npm install
npm run dev      # 開發模式啟動
npm run dist     # 打包 Windows exe 到 release/
```
