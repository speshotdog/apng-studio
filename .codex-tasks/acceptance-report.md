## 發現的問題

### P1：切換輸出目標會讓 Twitch 的 FPS／播放次數污染後續 LINE 設定

- 重現步驟：開啟 `11.clip`，在「輸出目標」依序選 `Twitch → 動態表情`、`YouTube → 會員表情`、`LINE → 動態貼圖`。
- 實際結果：切到 Twitch 動態表情時 FPS 被限制為最多 30、播放次數改為無限（0）；YouTube 將這兩項隱藏；再回 LINE 時只恢復格式與尺寸，FPS 仍是 Twitch 留下的值，播放次數仍為無限。LINE 檢查因此出現播放次數不合規，使用者必須自行找出並改回。
- 預期結果：切回 LINE 應套用該目標合理且合規的 FPS／播放次數預設，或恢復使用者上次在 LINE 的設定，不應承接另一平台的隱藏狀態。
- 原因：`selectTarget()` 只在 Twitch 動態分支寫入 `fps` 與 `playCount`，其他目標的 `targetDefaults` 沒有對應恢復；LINE 分支僅設定格式與尺寸。見 `src/renderer/components/ExportPanel.tsx:58`～`src/renderer/components/ExportPanel.tsx:109`，關鍵為第 68 行。

### P2：未設定 GIPHY 金鑰時，「上傳到 GIPHY」按鈕外觀與 disabled 狀態錯誤

- 重現步驟：設定頁清除 GIPHY 金鑰，載入 `11.clip`，回到匯出面板查看並點「上傳到 GIPHY」。
- 實際結果：按鈕只有在「未載入文件」或忙碌時才 disabled；沒有金鑰時仍是可按狀態。點擊後會開設定頁，雖不會直接上傳，但按鈕狀態與 title「請先到設定填入 GIPHY API Key」互相矛盾。
- 預期結果：依驗收需求，未設定金鑰時應清楚呈現不可上傳的狀態；若產品決定用點擊導向設定，至少應改成明確的「設定 GIPHY」動作，而不是顯示成可執行上傳。
- 原因：按鈕的 `disabled` 條件只有 `!doc || busy`，沒有檢查 `hasGiphyKey`；缺少金鑰的處理放在 click handler 內。見 `src/renderer/components/ExportPanel.tsx:179`～`src/renderer/components/ExportPanel.tsx:180`、`src/renderer/components/ExportPanel.tsx:601`～`src/renderer/components/ExportPanel.tsx:607`。

### P2：關鍵錯誤路徑與極端邊界尚無可交付等級的實際驗收證據

- 重現步驟：分別開啟損壞的 `.clip`、匯入空資料夾、保留空貼圖格後打包、以假金鑰按「測試連線」，再測格數 1／120、zoom 20%／400%。
- 實際結果：本輪現有的可操作 smoke 沒有完整走過上述 UI 路徑，因此無法確認錯誤訊息是否清楚、是否會白畫面，以及極端值下是否仍可操作。
- 預期結果：交付前應有實際 UI 操作證據，確認錯誤可理解且應用不崩潰。
- 原因：目前 `scripts/smoke.ts` 涵蓋正常匯出、拖放、可見性、FPS 1／60、構圖調整、快照及貼圖組成功路徑，但未完整覆蓋上述錯誤與格數／zoom 邊界。這是驗收缺口，不代表已確認存在功能 bug。
