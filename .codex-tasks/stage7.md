## 1. LINE 檢查結果被捲走了 —— 這是最該被看到的東西

`out/smoke/ui-line-ok.png`（1024×640）裡，右欄雖然設定全部合規
（270×270 / 6 FPS / 播放 4 次 / 單次 1.00 秒 / 總 4.00 秒），
但**綠色的「符合 LINE 動態貼圖規格」根本不在畫面上** —— 它被捲到統計區下面去了。

對插畫家來說，「這樣到底能不能上傳 LINE」是他每次匯出前唯一真正在問的問題。
它不該需要捲動才找得到。

### 改法

把 **LINE 檢查結果移到右欄底部的固定區塊**，跟「匯出」按鈕待在一起，不隨內容捲動：

```
┌ 右欄 ──────────────┐
│ （可捲動區）        │
│  格式 / 尺寸 / FPS  │
│  播放次數 / 合併    │
│  統計四項           │
│  ☑ LINE 規格檢查    │
├────────────────────┤ ← 這條以下固定不捲
│  ✅ 符合 LINE 規格   │   或  ⚠ 1 項警告 / ❌ 2 項錯誤
│  （條列訊息）        │
│  [ 匯出 APNG ]      │
└────────────────────┘
```

- 全部通過 → 綠色一行「符合 LINE 動態貼圖規格」
- 有問題 → 紅色 error 在前、黃色 warning 在後，逐條列出（訊息已經在 `line.ts` 寫好了）
- 訊息多的時候這塊自己有最大高度 + 內部捲動，但**「匯出」按鈕永遠看得到**
- 關掉「LINE 規格檢查」勾選時，這塊收起來，只留匯出按鈕

## 2. 圖層縮圖在打包版是空白的

比較兩張截圖：

- `out/smoke/ui-line-ok.png`（開發版）：`1 的複製`、`1a 的複製` 縮圖都畫得出羊
- `out/smoke/ui-packaged.png`（打包版）：`資料夾 1`、`1 的複製`、`1a 的複製`、
  `1b 的複製` 的縮圖是**一片空白**

預覽和影格軌的縮圖都正常，所以解碼沒問題 —— 是圖層面板的 lazy 縮圖在截圖當下還沒載完。

### 改法

1. `waitIdle()` 要真的等到**所有已掛載的圖層縮圖都畫完**才 resolve
   （目前顯然沒有，才會拍到半成品）。
2. 縮圖還沒載入時，不要顯示空白色塊 —— 給一個明顯是「載入中」的佔位
   （例如淡灰底 + 微弱的脈動動畫），使用者才不會以為那層是空的。
3. 在 smoke 加斷言：截圖前，圖層面板中**所有可見列的縮圖都必須已載入完成**
   （可以在 DOM 上放 `data-thumb-loaded="true"`，斷言沒有 `false` 的）。
